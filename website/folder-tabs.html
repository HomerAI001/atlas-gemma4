Sovereign Signal Vault

Atlas is architecturally incapable of reading user data. Encryption is end-to-end and split-key by design.

  • DeviceKey — PBKDF2 from user passphrase, never leaves the device
  • ServerKey — CSPRNG, stored server-side, rotated on breach
  • MasterKey — HKDF derivation of DeviceKey ⊕ ServerKey
  • Per-memory MemoryKey with AES-256-GCM edge encryption
  • Prompt Shield tokenisation before any LLM call
  • Burn Protocol — key destruction on user request

Data Sovereignty

The sovereign data architecture is not a feature. It is a philosophical position made structural. The entire framework rests on the premise that genuine presence requires the absence of institutional agenda.

"Sovereign data architecture means architectural incapability — not contractual prohibition. The system is built so that it cannot read your data, not merely promised not to."

  • Split-Key Architecture — DeviceKey (PBKDF2) + ServerKey (CSPRNG) combined via HKDF to produce MasterKey. Per-memory MemoryKey derivation. AES-256-GCM edge encryption throughout.
  • On-Device Tokenisation — Queries are tokenised on-device before transmission. Even the request payload is protected at the point of generation.
  • Discrete Encrypted Schemas — Each user has a discrete encrypted schema. No data exists server-side in readable form. Linking any record to a user requires that user's personal decryption key.
  • Burn Protocol — The user can destroy their data completely, at any time, without recourse. Key destruction renders all associated data permanently inaccessible. No recovery. No residue.

For this population, trust is not a nice-to-have. It is the precondition for everything else. The Sovereign Signal Vault is the structural guarantee that Atlas's presence is not conditional on compliance with data extraction.
